# Workspace memory

Durable **user instructions and preferences** for this Lisp workspace (similar in spirit to Claude Code's project memory). **Agents should read this file** when starting work here and **edit it** when the user states a preference that should persist across sessions.

Keep entries **short and actionable**. Remove or supersede items that go stale.

## How to use

- **User:** add bullets under the sections below, or tell the agent to record something here.
- **Agent:** after the user gives a standing instruction (tool choice, style, workflow, "always…", "never…"), add or update a line here and commit in `.lisp-workspace/` when appropriate.

## Preferences

- **Python touchpoints:** uv + ruff; line length 120; no black; modern typing (3.12+); optimize imports. **Not for CL repo scripts.**
- **CL project scripts = CL.** First-party CL repos dogfood cl-stack (`cl-stack-http` × `http-backend-async` × `event-backend-libuv`, pathlib, …). No Python/Node refresh/CI helpers for work the stack already covers. If a gold library exists only in another language, Lisp drives the sexp; freeze that dump rather than adding a second-language script.
- **HTTP client in first-party consumers:** bind `http-backend-async` × `event-backend-libuv` (`http-backend-async:*event-backend-maker*` + `http-protocol:*http-backend*`; http-parity `with-parity` shape). Dexador is maintenance — do not default new tests/docs/examples to it. Goal is dogfooding so we find stack bugs. `cl-stack-http` `:auto` on Unix still falls to dexador — prefer explicit `:async`.
- **Documentation:** terse; no verbose boilerplate.
- **CL errors = conditions + restarts.** First-party cl-stack uses CLHS 9 (not status-code returns, not Java exceptions). Standard restart names first; reuse Alexandria/UIOP/usocket/dexador/lparallel; pathlib `invoke-*` is sugar. Skill **cl-stack-conditions**.
- **CL MCP:** use [cl-ai-project/cl-mcp](https://github.com/cl-ai-project/cl-mcp), not the quasi/cl-mcp stack.
- **GitHub repos:** always use full `owner/repo` — never bare repo name when multiple owners share a name.

OCI client `:latest`. Packager: `ghcr.io/egao1980/cl-repository/cl-repository-packager:latest` (`v0.18.0`) via **`cl-repo:ensure-systems`** (source **and** native publish). **`publish-source.yml@main` verified** (schema-protocol:0.1.0, 2026-08-25). First-party copied scripts migrated 2026-08-25.
- **Canned CI reads the `.asd`.** Install walks SUT `:depends-on` + `/tests` via `ensure-system-dependencies` (no ASDF-load of overlays). `:ci :with` / `:sources` / `:load-before-test` / `:record-versions` for extras not in the asd. Phase split stays: install then test. Client order = OCI then QL.
- **No sibling checkouts (CI + install path).** Allowed `actions/checkout` in a consumer workflow: **only the repo under test**. Bootstrap `cl-repository-client` via **GHCR OCI** (above). Forbidden: checking out `cl-repository`, `http-protocol`, `event-protocol`, `event-backend-*`, `cl-stack-ssl`, or any other dep as a sibling path for ASDF. Deps come from **GHCR via cl-repo** (QL fallback only for unpublished). Workspace sibling clones for *local editing* are fine; never treat them as the CI/install dependency source.
- **Publish metadata = `.asd`.** `auto-package-spec` reads ASDF fields + `:properties (:cl-repo …)` (`:provides` / `:cffi-libraries` / `:overlays`). That is enough — no hand-written `package-spec` in repo scripts. Skill: **`cl-repository-ci`**. **Never pack `.cl-repository`** (setup-client bootstrap) — hide it after loading the packager; 0.16.0 `*excluded-dirs*` does not skip it (sse-protocol:0.1.0 first publish was a 10MB broken layer).
- **Who publishes where (GHCR ACL):** Package write is tied to the **owning GitHub repo**. **First-party `egao1980/<repo>`** → publish **from that repo** (`publish-source.yml` reusable / native reusable workflow). Do **not** route owned first-party packages through `cl-stack-systems`. **`cl-stack-systems`** = **third-party / unmodified** imports only. Natives stay on the reusable native workflow in the owning repo. **sql-query-postgres / sql-query-sqlite3** packages were first published from `sql-query` — owning-repo publish is still 403 (2026-08-25); keep `sql-query` `publish_dialects` until Package → Manage Actions access grants Write. - **Fork ↔ import exclusivity:** never both for the same upstream. Fork ⇒ delete `imports/<name>/` of upstream.
- **Native overlays:** resolve via `cffi:*foreign-library-directories*` + absolute preload (`cl-repo-init.lisp` / `ensure-*`). **Never** require `LD_LIBRARY_PATH` / `DYLD_LIBRARY_PATH` for correctness (Linux ignores mid-process `setenv`; see cl-repository `docs/requirements/native-deps.md`).

Idempotent internal helpers OK; do not export “you must call this first” as part of the DX.
- **No `:ql` source pins.** `:sources (("foo" :ql))` forces Quicklisp and bypasses OCI. If CI needs `foo`, it must already be on `ghcr.io/egao1980/cl-systems` — add a `cl-stack-systems` import (third-party) or publish from the owning `egao1980/<repo>` (first-party). Then drop the pin. Client order is already OCI then QL, so unpublished leftovers still QL-fallback without a pin. **Do not** invent `:ql` pins as a workaround.
- **cffi OCI:** `ghcr.io/egao1980/cl-systems/cffi:0.24.1` (+ `cffi-grovel:0.24.1`; same pin). Upstream asd has no `:version` — publish forces it.

- Plan before acting on new projects or massive changes; use git to preserve initial state and track in a branch.
- Run tests before declaring done.
- Use feature branches in subproject repos.
- **Before deleting "dead" code** (unused params/vars/functions), check it isn't scaffolding for a planned-but-unimplemented feature — grep TODO/docs/requirements + `git log -S`. If planned: keep it and document the reserved intent (e.g. `;; TODO(<area>)`) rather than removing.
