# CI / OCI / publish notes

Read with skill **[cl-repository-ci](../skills/cl-repository-ci/SKILL.md)**. Policy: [REQUIREMENTS.md](../docs/REQUIREMENTS.md).

## Contract (do not weaken)

- **Package / project deps = cl-repository.** CI and local installs use `cl-repository-client` against `ghcr.io/egao1980/cl-systems`. **Consumer CI:** canned `egao1980/cl-repository/.github/workflows/test-system.yml@main` (or `setup-lisp` + `ci` with `phase: install|test`). OCI client `:latest`. Packager: `ghcr.io/egao1980/cl-repository/cl-repository-packager:latest` (`v0.18.0`) via **`cl-repo:ensure-systems`** (source **and** native publish). publish-source.yml@main verified (schema-protocol:0.1.0, 2026-08-25). Native `publish-native-package.yml` is the same Lisp load path — **no** apt SBCL / Quicklisp bootstrap / raw `oras pull` of the packager tarball. Binaries stay in overlay artifacts. **`uses:` refs must be literal `@main`** (GH does not interpolate `inputs`/`github` there). **Do not git-checkout `cl-repository` in consumer CI.** No qlot / sibling checkouts / hand-rolled `oras pull` of natives for *project* deps. **Do not copy `ci-install.lisp` / `ci-test.lisp` / `publish-checkout.lisp`.** Extras → `.asd` `:properties (:cl-repo (:ci …))`; hooks → `scripts/ci/` only if canned cannot express the step. First-party copied scripts migrated 2026-08-25.
- **Canned CI reads the `.asd`.** Install walks SUT `:depends-on` + `/tests` via `ensure-system-dependencies` (no ASDF-load of overlays). `:ci :with` / `:sources` / `:load-before-test` / `:record-versions` for extras not in the asd. Phase split stays: install then test. Client order = OCI then QL.
- **No sibling checkouts (CI + install path).** Allowed `actions/checkout` in a consumer workflow: **only the repo under test**. Bootstrap `cl-repository-client` via **GHCR OCI**. Forbidden: checking out `cl-repository`, `http-protocol`, `event-protocol`, `event-backend-*`, `cl-stack-ssl`, or any other dep as a sibling path for ASDF. Deps come from **GHCR via cl-repo** (QL fallback only for unpublished). Workspace sibling clones for *local editing* are fine; never treat them as the CI/install dependency source.
- **Publish metadata = `.asd`.** `auto-package-spec` reads ASDF fields + `:properties (:cl-repo …)` (`:provides` / `:cffi-libraries` / `:overlays`). That is enough — no hand-written `package-spec` in repo scripts. **Never pack `.cl-repository`** (setup-client bootstrap) — hide it after loading the packager; 0.16.0 `*excluded-dirs*` does not skip it (sse-protocol:0.1.0 first publish was a 10MB broken layer).
- **Who publishes where (GHCR ACL):** Package write is tied to the **owning GitHub repo**. **First-party `egao1980/<repo>`** → publish **from that repo** (`publish-source.yml` reusable / native reusable workflow). Do **not** route owned first-party packages through `cl-stack-systems`. **`cl-stack-systems`** = **third-party / unmodified** imports only. Natives stay on the reusable native workflow in the owning repo. **sql-query-postgres / sql-query-sqlite3** packages were first published from `sql-query` — owning-repo publish is still 403 (2026-08-25); keep `sql-query` `publish_dialects` until Package → Manage Actions access grants Write. If a first-party package was first published from the wrong repo, delete it (`delete-package.yml` on the linked repo) and republish from the owner — do not keep a proxy publish job.
- **Fork ↔ import exclusivity:** never both for the same upstream. Fork ⇒ delete `imports/<name>/` of upstream.
- **Native overlays:** resolve via `cffi:*foreign-library-directories*` + absolute preload (`cl-repo-init.lisp` / `ensure-*`). **Never** require `LD_LIBRARY_PATH` / `DYLD_LIBRARY_PATH` for correctness (Linux ignores mid-process `setenv`; see cl-repository `docs/requirements/native-deps.md`).
- **CFFI natives auto-load on ASDF load:** first-party native packages (`cl-stack-icu`, `cl-stack-zstd`, …) must `load-foreign-library` (absolute preload preferred) at system load — typically `(eval-when (:load-toplevel :execute) …)` at the end of the FFI file. **No** consumer `load-*` / `ensure-*` calls required to use the API. Idempotent internal helpers OK; do not export “you must call this first” as part of the DX.
- **No `:ql` source pins.** `:sources (("foo" :ql))` forces Quicklisp and bypasses OCI. If CI needs `foo`, it must already be on `ghcr.io/egao1980/cl-systems` — add a `cl-stack-systems` import (third-party) or publish from the owning `egao1980/<repo>` (first-party). Then drop the pin. Client order is already OCI then QL, so unpublished leftovers still QL-fallback without a pin. **Do not** invent `:ql` pins as a workaround.

## Pins

- **cffi OCI:** `ghcr.io/egao1980/cl-systems/cffi:0.24.1` (+ `cffi-grovel:0.24.1`; same pin). Upstream asd has no `:version` — publish forces it.
- **log4cl OCI:** `ghcr.io/egao1980/cl-systems/log4cl:1.1.4` (sharplispers `fe3da517`; `v1.1.2` package-locks on SBCL 2.6.7).
- **rove OCI:** `ghcr.io/egao1980/cl-systems/rove` ([`egao1980/rove`](https://github.com/egao1980/rove); `deftest-parametrize`). `:depends-on ("rove")` on `/tests` is enough — no `:ci :sources`.

## Overlay keys + local OCI

- **cl-repository overlay keys:** platform specs support **`os` / `release` / `arch`** (not just `os` / `arch`). Overlays can be keyed per distro release (e.g. `ubuntu-24.04/arm64` vs `ubuntu-26.04/arm64`) when native binaries are glibc-sensitive. Current workflows use bare `linux` / `darwin` — sufficient while building on the oldest supported LTS.
- **OCI publish + consumer test (cl-protobufs / grpc):** run **`act`** against `publish-oci.yml` with local registry + artifact server, then verify in a **roswell devcontainer** with **`cl-repository`** mounted and `host.docker.internal` to the registry. Full command pattern and pitfalls → **[LESSONS_LEARNED.md](../LESSONS_LEARNED.md)** (section *act + local OCI registry + devcontainer*).
