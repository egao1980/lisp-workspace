# Staged improvements for team-solve

## Pending


- [2026-11-26] A solver waiting on its own long test run started a new background `until grep -q MARKER log; do sleep 30; done` loop each time it checked back, instead of reusing the one it had: 31 waiters on one run after 90 minutes, plus 3 whose log had stopped and whose marker could never appear, all listed as running tasks. Proposal: solver, repair and contract prompts say to start at most one waiter per run, include a timeout and the run's pid in its condition (`kill -0 $PID`), and stop it when done.
- [2026-11-26] cl-stack-code H3e-2b (#54): (8) a test that binds a special with LET and expects a callback on another thread to see it can never pass. `req` / `within` run the call on a new thread, and a loopback peer answers on its own dispatch thread. The fix was SETF plus UNWIND-PROTECT, in a test-only commit by user decision. Add it to the contract-author checklist next to (1)–(7). (9) The step agents' shells put Apple's /usr/bin/git 2.54 first, so 38 git-kind tests failed for the solver (revision-backend-git needs 2.56). The coordinator's PATH, with /opt/homebrew first, passed. Proposal: the step-prompt boilerplate carries the PATH line (`export PATH=/opt/homebrew/bin:$HOME/.local/bin:$HOME/.roswell/bin:$PATH`), and check-feature.sh could print `git --version`. (10) A protocol contract PR (ai-agent-protocol#45) had no `.team-solve/task.md`. The coordinator wrote one into the ledger from the PR body and the brief. Proposal: the contract step commits task.md, or the skill says the coordinator writes it when it is missing.

- [2026-11-24] Parallel agents share one session scratchpad. Two contract agents wrote their throwaway reference implementations into the same generic `scratchpad/ref/`. One ran `rm -rf scratchpad/ref`; the other overwrote LICENSE, README and the package files in it. Proposal: contract, ideator and solver prompts say to use a scratch subdirectory named after the repo and run (e.g. `scratchpad/<repo>-<slice>-ref/`), never generic names (`ref`, `probe`, `tmp`), and never to `rm -rf` a directory the agent didn't create in this run.
- [2026-11-19] agent-tools H2b contract: (6) `(find-restart 'name c)` skips restarts associated (CLHS 9.1.4.2.2) with another condition — pathlib's OVERWRITE belongs to its own CONTENT-HASH-MISMATCH, so a test handler for a re-signalled wrapper condition must call `(find-restart 'name)` without C; (7) `ai-agent-protocol:agent-unknown-tool` is not an ERROR, so a `handler-case … (error …)` test helper misses it and the image lands in the debugger. Cheapest guard found: before sealing, load a throwaway prototype (scratchpad, not committed) over the stubs and run the suite — it caught three test bugs and one stack bug (cl-stack-pathlib#23) here.

- [2026-11-27] check-feature.sh: seal only tracked test files. `--seal` hashes every file under `tests/`, including git-ignored ones (e.g. `tests/fixtures/__pycache__/*.pyc` left by a fixture generator) and records absolute paths. An ignored cache file appearing or vanishing, or running the seal from a symlinked spelling of the path (`/tmp/...` vs `/private/tmp/...` on macOS), then fails the run before Lisp starts. Proposed fix: hash `git ls-files -z tests/` (plus task.md and the brief) with repo-relative paths, falling back to `find` only outside a git checkout.
- [2026-11-27] The seal hashes the brief in place, at its absolute path in a shared checkout (the workspace cl-stack, which other sessions pull and commit in). transcribe-backend-pyin T1: the contract agent merged the brief's T1 section upstream; the coordinator sealed before pulling, pulled mid-run, and the test step failed with "contract changed" before Lisp started. The planner had also read the pre-T1 brief and flagged four brief-vs-contract conflicts that were only staleness. Fix used: put the sealed brief (git show <sealed commit>) in place for the check only, recorded in notes.md. Proposal: the coordinator pulls the brief's checkout before sealing (as already learned for "brief not found"), and `--seal` copies the brief into `.team-solve/brief.md` and hashes that copy (task.md's brief path then only says where it came from), so later pulls cannot break a run.
